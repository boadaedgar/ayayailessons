Sección 1 — La idea

01

Qué Es Git, en Serio

Una idea, y de ahí sale todo lo demás.

↓ para profundizar
01 · Concepto

Git Guarda Fotos, No Archivos

Cuando le das "Guardar" a un documento, el archivo anterior desaparece. Se sobrescribe. Si mañana te arrepientes, no hay vuelta atrás.

Git funciona distinto: cada vez que le dices que guarde, saca una foto de toda la carpeta y la archiva con fecha y una nota tuya. La foto de ayer sigue ahí. La de la semana pasada también.

Por eso se dice que git nunca olvida. No es una forma de hablar — es literal. Todo lo que entró alguna vez, se queda.
01 · Concepto

Repositorio: la Carpeta Vigilada

Un repositorio — o "repo" — es simplemente una carpeta que git está vigilando. Por fuera se ve igual que cualquier otra carpeta.

La diferencia está en una subcarpeta escondida llamada .git, donde viven todas esas fotos. Si borras .git, pierdes el historial y te queda una carpeta normal.

Cada proyecto es su propio repositorio. No metes todo en uno solo — igual que no guardas los papeles del carro en la carpeta del colegio de los muchachos.

Ahí está toda la diferencia: el commit es local, el push es el envío.
02 · Consecuencias

Qué Significa Eso en la Práctica

  • Puedes hacer commits sin internet. Diez, veinte. Y los subes todos después con un solo push.
  • Commit sin push = solo en tu computadora. Si se daña el disco, ese trabajo se perdió. GitHub no sabe que existe.
  • Push sin commit no existe. Solo se manda lo que ya está en un sobre cerrado.
El error clásico: trabajar toda la semana haciendo commits y no hacer push nunca. Se siente como que está guardado — y lo está, pero en un solo lugar.
02 · En la práctica

Cómo Se Ve de Verdad

# Ver qué cambió desde la última foto
git status

# Meter todo lo cambiado en el sobre
git add .

# Cerrar el sobre con una nota de qué hiciste
git commit -m "Agrego la guía de ejercicios de equilibrio"

# Mandarlo a GitHub
git push
La nota del commit importa. Dentro de seis meses, "cambios" no te dice nada. "Agrego la guía de ejercicios de equilibrio" sí.
02 · El otro lado

Y Para Traer, No Mandar

ComandoQué hace
git cloneTraer un repositorio completo la primera vez. Se hace una sola vez.
git pullBajar los cambios que subió alguien más — o tú desde otra computadora.
Si trabajas en dos computadoras: pull antes de empezar, push al terminar. Si no, se te enredan las versiones.
Sección 3 — Público y Privado

03

Público vs Privado

La parte donde la gente se quema. Incluidos nosotros.

↓ para profundizar
03 · La regla

Una Sola Pregunta

¿Qué pasa si esto se hace público mañana?

Si la respuesta no es "nada", va en un repositorio privado.

Lo privado es el default. Público es una decisión que tomas a propósito, no algo que pasa porque no lo pensaste.
Un repositorio público es un archivador sin puerta. Cualquiera puede entrar, mirar, y llevarse copia — sin avisarte y sin dejar rastro.
03 · Lo importante

Público Es Para Siempre

Esta es la parte que sorprende a todo el mundo: borrar un archivo no lo saca del historial. Git guarda fotos, ¿recuerdas? El archivo sigue en la foto de ayer.

Y si eso ya estuvo publicado, hay que asumir que alguien pudo haberlo copiado.

Sacarlo de verdad requiere reescribir todo el historial, y hasta después de eso hay que pedirle a GitHub que limpie su caché. Es un dolor de cabeza evitable.
La regla que te ahorra todo eso: pensarlo antes del primer commit, no después.
03 · Qué nunca sube

Lo Que Nunca Va a un Repo Público

QuéPor qué
Contraseñas y claves de accesoHay programas que rastrean GitHub buscándolas. En minutos.
Datos de una empresaInventarios, precios, planes de producción. No son tuyos para publicarlos.
Datos de personasNombres, teléfonos, correos, historias clínicas.
Cosas personales tuyasCurrículos, finanzas, borradores privados.
Si dudas, es privado. Pasar de privado a público después es un clic. Al revés, no.
Sección 4 — .gitignore

04

El Archivo .gitignore

La red de seguridad. Un archivo de texto que evita disgustos.

↓ para profundizar
04 · Qué es

La Lista de lo Que Git Debe Ignorar

Es un archivo de texto llamado .gitignore, en la raíz de tu proyecto. Cada línea es algo que git debe hacer como si no existiera: no lo guarda, no lo sube, ni te lo menciona.

# Datos reales del cliente — no se publican
datos-clientes/

# Cosas personales
finanzas/

# Basura que genera la computadora
__pycache__/
*.tmp
04 · Cuándo

Escríbelo Antes del Primer Commit

Este es el orden que importa. Si el archivo ya entró en una foto, agregarlo al .gitignore después no lo saca del historial — solo evita que entre otra vez.

1
Creas la carpeta del proyecto
2
Escribes el .gitignore
antes de tocar git
3
Ahora sí, el primer commit
Poner un comentario diciendo por qué ignoras cada cosa te lo agradece tu yo de dentro de un año.
Sección 5 — Recuperar

05

Recuperar Algo Viejo

La ventaja de que git nunca olvide.

↓ para profundizar
05 · Etiquetas

Ponerle Nombre a un Momento

Un tag es una etiqueta con nombre pegada sobre una foto específica. Sirve para marcar momentos que quieres poder encontrar sin buscar entre cien fotos.

# Al cerrar la temporada 1 del curso
git tag temporada-1-final
git push --tags
Ejemplos de buenos tags: el fin de una temporada, la versión que le entregaste a un cliente, el día antes de un cambio grande.
05 · Sacar un archivo

Traer de Vuelta Algo que Ya no Está

Con la etiqueta puesta, recuperar cualquier archivo de esa época es una línea — aunque lo hayas borrado de la carpeta hace meses.

# Ver cómo era ese archivo en aquel momento
git show temporada-1-final:guias/leccion-vieja.html

# Traerlo de vuelta a la carpeta
git checkout temporada-1-final -- guias/leccion-vieja.html
Por eso "ya no lo uso" no significa "hay que botarlo". Lo sacas de la carpeta para no tener desorden, y sigue estando ahí cuando lo necesites.
05 · Enlaces

Ojo con Mover Archivos Publicados

Si tu proyecto es una página web publicada, la dirección de cada archivo depende de en qué carpeta está. Mover el archivo cambia su dirección — y los enlaces que ya compartiste dejan de funcionar.

La solución sencilla: no muevas nada. "Archivar" es decidir qué sigues enlazando desde la página principal, no cambiar los archivos de sitio. Así ningún enlace que mandaste se rompe nunca.

06 · Cuidado

Dos Palabras de Cuidado

PalabraPor qué tener cuidado
force push Sobrescribe el historial de GitHub con el tuyo. Borra trabajo de otros sin preguntar. No se usa sin saber exactamente por qué.
git reset --hard Bota todos los cambios que no has guardado en un commit. No hay papelera de reciclaje.
Si un comando lleva --force o --hard, pregunta antes de darle Enter. Esa es toda la regla.
